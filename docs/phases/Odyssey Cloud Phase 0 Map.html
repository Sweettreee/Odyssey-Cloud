7. What P4 denies the pipeline

The apply role has AdministratorAccess, but its permissions boundary P4 removes these. Every role or user the pipeline creates must carry P4 too. P4 is about 4,210 of 6,144 characters; it gets restructured at 80%.

ProtectsDeny statements
Its own identityDenyBootstrapIamChanges, RequireBoundaryOnIamWrites, DenyBoundaryRemoval, DenyIamGroupWrites
Humans and sign-inDenyLongLivedCredentials, DenyMfaChanges, DenyNewIdentityProviders
AccountDenyAccountLevelChanges (incl. account S3 Block Public Access), DenyOutsideSeoul
StateDenyStateBucketConfig, DenyStateObjectHistoryAndAcl, DenyBootstrapState, DenyMainStateDelete
Logs and alertsDenyLogBucketConfig, DenyLogObjects, DenyLoggingAndAlertServices, DenyAlertRuleChanges, DenyDefaultBusUpdate, DenyEventBusPermissionChanges, DenyAlertTopicChanges

Exit criteria

  • Every resource exists because of code, except those from E1–E6 and E10.
  • Changes to main reach the cloud only through the pipeline; bootstrap follows E7.
  • Test alerts for every budget threshold reach Slack (a temporary USD 0.01 budget, added and removed through E7).

Later, not now

  • Paid-plan transition: management account, Organizations, Identity Center, a sensitive-data account, SCPs and RCPs.
  • Phase 1: ec2:InstanceType allowlist in P4.
  • Phase 2: how application deploys authenticate.
  • Phase 4: reading CloudTrail logs older than 90 days.
